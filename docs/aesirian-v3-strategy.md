# Æsirian — FP重塑·方法论注册表·产品路线图 v3.0

## 第一部分：First Principles 重塑

### FP 1.0（旧）→ 诊断

> 叙事不是文本生成，而是认知建构。

**问题**：完整但片面。只看到"建构一致的叙事模型"，没看到"创造独特的叙事体验"。一致性服务于体验，不是体验服务于一致性。

### FP 2.0（新）

> **叙事是"作者意图 → 文本介质 → 读者体验"三极之间的全息协同。**
>
> 文本在这个协同中起双重作用：它是读者建构叙事模型的**介质**（认知层），也是读者获得情感冲击和审美体验的**材料**（体验层）。
>
> 系统不替代任何一极。系统做三件事：
> 1. **保障协同的完整性** — 多极之间的信息不丢失、不扭曲（门禁 + KG）
> 2. **降低协同的认知成本** — 让作者和读者都不被无关复杂度淹没（读者模型 + ToM可视化）
> 3. **保留涌现和惊喜的空间** — 不让系统约束杀死创作的"意外之喜"（破坏约束版本 + 发散引擎）

### FP 的工程推论

| FP | 工程推论 |
|-----|---------|
| 叙事是三极协同 | 系统维护三重视角：作者意图状态 / 文本事实状态 / 读者可能模型状态 |
| 文本是介质也是材料 | 门禁既要保"正确"（介质功能），也要保"有效"（材料功能） |
| 完整性 | 时序KG保障时间/空间/因果链不矛盾 |
| 降低认知成本 | 读者模型预测"更新成本" → 建议作者在认知负荷过高时缓一缓 |
| 保留涌现 | 门禁区分"OOC错误"和"弧光突变" → 前者阻断，后者标记 |

新的FP更**辩证**——承认创作本身包含着矛盾（一致vs意外、结构vs涌现、作者vs读者），系统不是消除矛盾，而是在矛盾中导航。

## 第二部分：方法论注册表

### 2.1 设计原则

方法论注册表是Æsirian的 "元策略层"——跑在底层引擎之上，用知识底座里30+方法论体系驱动发散、评价、约束和审计策略的选择。

每个方法论是一个可执行的策略节点，包含：
- **触发条件** — 什么场景下激活
- **输入** — 需要什么上下文
- **输出** — 生成什么类型的策略指令
- **关联方法** — 可以组合使用的方法
- **评分维度** — 如何评估应用效果

## 第三部分：产品形态

### 3.1 定义

> **Æsirian = 一个让任何人在任何阶段都能参与叙事创作的"三极协同引擎"。**

用户提供什么都可以：
- 一个模糊想法 → 系统发散出3-5个故事种子
- 一个画面/碎片 → 系统编织进叙事线索
- 一段草稿 → 系统识别剩余潜能，建议分支方向
- 一个类型/风格偏好 → 系统匹配类型契约，约束生成策略
- "我觉得不对" → 系统退回上一个分支点，换方向

### 3.2 产品形态演变

```
现在（v0.1）：后端引擎 + Web控制台
  └── 技术验证，api可用
  └── 角色: 命令行 + 浏览器调试

Phase 1（4周后）：叙事沙盒
  └── 从碎片到故事种子的Web界面
  └── 发散-选择-收敛-延展循环可视化
  └── 心智网格（角色信念状态图）
  └── 门禁审计面板（BLOCK/WARN/PASS）
  └── 角色: 普通创作者可在浏览器用

Phase 2（10周后）：写作伴侣
  └── 写作画布（心流模式）
  └── 续写建议（Ctrl+Enter）
  └── 假设推演（"如果角色信念变了会怎样"）
  └── 多世界线管理（发酵池可视化）
  └── 角色: 严肃作者可每日使用

Phase 3（20周后）：叙事工作室
  └── 桌面 Electron IDE
  └── 双模式（心流↔分析）
  └── 方法论注册表可视化（"当前使用什么方法在驱动"）
  └── 风格档案共享市场
  └── 角色: 专业创作者的日常工具
```

### 3.3 关键体验设计

**零门槛输入的"漏斗"：**

```
用户输入        系统处理          用户决策
────────         ──────           ──────
一句话想法   →   发散3-5方向   →   选一个
一个画面     →   编织进线索     →   调整或接受
一段草稿     →   提取剩余潜能   →   确定方向
"不知道"     →   三次驯化提问   →   回答问题
类型+风格    →   匹配契约约束   →   确认
```

每个节点用户都可以：
- **接受** → 系统继续
- **修改** → 系统重新生成
- **拒绝+换方向** → 系统退回上一个分支点
- **"再来一个"** → 系统发散更多方向

## 第六部分：方法论注册表 → 代码启动

### Phase A 第1周任务

方法论注册表的核心数据结构已经清晰。可以直接映射为代码：

```python
@dataclass
class MethodologyNode:
    """一个可执行的方法论策略节点"""
    id: str                          # M001, M002...
    name: str                        # 英雄之旅
    family: str                      # narrative_structure
    source: str                      # Joseph Campbell, 1949
    trigger_conditions: list[str]    # ["story_arc_planning", "structure_check"]
    input_type: str                  # "fragment", "chapter", "arc"
    output_type: str                 # "direction", "strategy", "constraint"
    weight: float = 1.0
    enabled: bool = True

class StrategyRegistry:
    """方法论注册表"""
    def get_strategies(self, input_type: str, context: dict) -> list[MethodologyNode]: ...
    def apply(self, node: MethodologyNode, input_data) -> StrategyResult: ...
    def chain(self, nodes: list[MethodologyNode]) -> StrategyChain: ...
```

这是Phase A第1周的交付物。
